Проверены fork `3412b2e2`, production `af49c54b` на `omni-fr` и
[тег upstream v0.5.119](https://github.com/decolua/9router/releases/tag/v0.5.119)
(`1855aa44`). От общего предка `1339107e` — 39 upstream-коммитов,
116 изменённых файлов и 23 конфликтующих файла в пробном слиянии.

Upstream не меняет `src/lib/db`; повторять перенос Qubax не нужно.

## Логи production

- **Kiro.** Три активных Builder ID на AWS `us-east-1`, без привязанного proxy.
  Последнее успешное обновление — 8 ноября, до перехода на 0.5.116;
  access tokens просрочены. Проба из production-контейнера без токенов:
  три из трёх POST на OIDC с текущим `X25519` оборвались с `ECONNRESET`
  до TLS; три из трёх с `X25519:P-256` вернули ожидаемый для неполного
  запроса HTTP 400 `invalid_request`. Настройка `X25519` остаётся в 0.5.119.
  Исправить TLS для точного AWS OIDC endpoint, сохранив настройки Claude
  и проверку сертификатов. Затем проверить настоящий refresh одного аккаунта:
  транспортная причина подтверждена, действительность просроченных credentials
  не проверялась. Если AWS отклонит refresh token или client registration,
  переподключить затронутые аккаунты. В логах фонового refresh полезен безопасный
  код причины (`ECONNRESET`, HTTP status) без секретов.
- **Qubax.** Три запроса 13 ноября в 11:48 МСК вернули
  `provider must be a string or an array of strings.` на первом члене Combo;
  все три завершились через следующий OpenRouter. В доступных логах с последнего
  запуска — больше 1 270 таких ошибок. Это отдельная несовместимость форматов:
  Qubax принимает строку или массив строк, OpenRouter может принимать объект.
  Историческое тело запроса не сохранилось. Уточнить форму на тестовом запросе
  и исправить на границе Qubax Chat Completions. Не передавать в Qubax чужие
  настройки роутинга и не отбрасывать молча ограничения выбора продавца;
  валидные строки/массивы и OpenRouter fallback должны сохранить поведение.
  Проверить с tools на реальном пути Combo; запросы с production-ключами
  при анализе не запускались.
- **Caddy.** Оба сообщения — `reading: context canceled` на
  `POST /v1/chat/completions` через 17.06 и 18.81 с, с User-Agent
  `trading-intelligence/0.1`. Это совпадает с идентификатором клиента
  TraidingBot; конкретный клиентский deadline пока не подтверждён.
  На этом маршруте в Caddy нет заданного таймаута, рестартов Caddy и
  9router не было, локальный health ответил OK. Сверить времена запросов
  с отменами/таймаутами клиента, прежде чем менять настройки Caddy или 9router.

## Какие контейнеры хранить

Все шесть остановлены и используют тот же именованный том `9router-data`,
что и работающий контейнер. У всех шести есть локальные теги образов.

| Действие | Контейнер | Причина |
| --- | --- | --- |
| Оставить | `9router-before-qubax-quota-20261109-af49c54b` | Последний откат до изменения квот, образ `a79314fc`. |
| Оставить | `9router-before-qubax-20261109-a79314fc` | Откат до переноса Qubax, образ `14d4372e`; требуется база из той же точки. |
| К удалению | `9router-before-models-performance-20261109-14d4372e` | Промежуточный образ `f0f0dbab`. |
| К удалению | `9router-before-models-performance-20261109-f0f0dbab` | Образ исходного обновления 0.5.116. |
| К удалению | `9router-before-upstream-v0.5.116-20261108-4ef0c7a4` | Более ранний образ до 0.5.116. |
| К удалению | `9router-rollback` | Самый старый образ из списка. |

Для двух сохраняемых точек архивы находятся в
`/root/9router-releases/{qubax-quota-20261109-af49c54b,qubax-20261109-a79314fc}/backup`;
в обоих есть конфигурация контейнера и SQLite, `PRAGMA quick_check` вернул
`ok`. Если чистить, удалить только четыре указанных остановленных контейнера
после повторной сверки имён и статусов. Не удалять образы, том или архивы.
Это очищает список; слои образов останутся на диске.

На этапе анализа слияние, исправления, деплой и удаление не выполнялись.
